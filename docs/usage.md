# 🎮 核心交互指南

GitMindHub 的交互设计深度借鉴了 Git 的工作流，以下是核心功能的使用说明。

## 1. 开启新对话 (New Root)

- 点击顶部导航栏的 `✨ 新建对话`。
- 或者在空白输入框直接输入你的第一条消息。
- 系统将创建一个全新的 Root 节点（类似于 Git 中的初始 Commit）。

## 2. 分支探索 (Fork & Checkout)

这是 GitMindHub 最核心的交互。当你想基于某个历史节点尝试不同的 Prompt 时：

1. 切换到顶部的 `🕸️ DAG 视图`。
2. 找到你想要分叉的历史节点。
3. **双击该节点**。
4. 系统会自动 **Checkout** 到该节点（右侧聊天区会显示到该节点为止的完整上下文）。
5. 在底部输入框追加新的对话。
6. 在 DAG 视图中，你会看到一条新的分支自然生长出来。

## 3. 语义搜索 (Local RAG)

- 点击顶部导航栏的 `🧠 语义查找`。
- 输入自然语言（例如：“之前讨论的那个布局算法”）。
- 系统会在本地的 LanceDB 向量库中进行语义检索。
- 点击搜索结果，系统会直接跳转到关联的对话节点，并自动切换为对话视图。

## 4. 数据备份与迁移

- **导出**：点击 `📤 导出`，系统会将完整的对话树（SQLite）和向量数据（LanceDB）打包为一个结构化的 JSON 文件。
- **导入**：点击 `📥 导入` 选择 JSON 文件。
    - 如果本地为空，将直接覆盖导入。
    - 如果本地已有数据，系统会弹出提示，支持**智能合并 (Merge)**。合并逻辑会自动处理 UUID 冲突，并修复悬空的 `parent_uuid`（将其截断为新的 Root），确保导入不会破坏现有的对话图谱。
